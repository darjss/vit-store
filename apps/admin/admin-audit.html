Admin product and UX audit

Stabilize the workflows, then redesign the system.

A verified backlog for the Amerik Vitamin admin, covering data integrity, forms, accessibility, responsive behavior, architecture, performance, and a measured migration toward storefront-v2 foundations.

30 verified findings 0 critical 6 high severity Artifact scope: apps/admin

Executive summary

The fastest route to a trustworthy redesign is to fix behavior before changing appearance.

The audit found six high-severity issues. Four are confirmed workflow or data-integrity bugs: fabricated dashboard analytics, destructive product editing from partial search results, brand edits routed to create, and shipping that discards unsaved order edits. Core interaction semantics and the failing type-safety gate complete the high-severity set.

The remaining backlog is substantial but sequenced: 17 medium findings cover date handling, routing, dialog and mutation state, CSS tokens, form semantics, responsive behavior, motion, state ownership, overfetch, and bundle size. Seven low findings define a safe storefront-v2 migration direction without importing retail-only patterns.

Redesign principle Treat storefront v2 as a source of tokens, accessibility behavior, and restrained visual cues. Preserve admin density and workflow structure; do not share framework-specific component trees or consumer merchandising patterns.

Storefront-v2 migration themes

Borrow the foundation signals that improve trust and usability. Keep admin behavior and density native to its own workflows.

  • 1. Semantic foundation

    Adopt a shared vocabulary for warm canvas, surfaces, ink, quiet borders, focus, status, and charts. Define every Tailwind v4 utility and eliminate stale aliases.

  • 2. Framework-neutral sharing

    Share tokens and variant recipes only. Maintain separate React/Radix and Solid/Kobalte behavior adapters.

  • 3. Admin-native composition

    Normalize primitives first, then extract recurring route anatomy, metrics, panels, toolbars, status badges, empty states, and form sections.

  • 4. Operational typography

    Use locally served Onest as the workhorse, sentence case, readable metadata, clear hierarchy, and tabular numerals. Avoid consumer display treatments in dense UI.

  • 5. Task-oriented feedback

    Prefer route-shaped skeletons, delayed navigation progress, inline mutation states, and localized recovery over ornate global loaders and blocking overlays.

  • 6. Explicit guardrails

    Do not port washes, retail cards, floating navigation, purchase-stack variables, celebrations, decorative patterns, entrance staggering, hard shadows, or oversized z-indexes.

Suggested phased roadmap

Each phase has an exit condition so visual work does not conceal behavioral regressions.

  1. Phase 1

    Stabilize bugs

    Fix fabricated analytics, partial-product editing, brand update routing, shipping with dirty state, Ulaanbaatar date serialization, product-add auth routing, customer dialog closure, search filtering order, duplicate submits, and write-form types. Exit: focused reproductions pass; type check is green.
