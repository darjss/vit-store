- **Source:** qa-products ISSUE-001
- **Screenshot:** `qa-products-shots/products-add-silent-500.png`

**Repro**
1. `/products/add` → click "Гараар нэмэх".
2. Fill valid data (name, description ≥5 chars, brand, category, price 25000, stock 5, potency, amount, daily intake 1, status draft).
3. Click "Бүтээгдэхүүн нэмэх".
4. `POST /trpc/admin/product.addProduct?batch=1` returns **500** `{"message":"Failed to add product","code":"INTERNAL_SERVER_ERROR"}`. URL stays on `/products/add`, no toast, no redirect. Product is NOT created (verified absent from draft list).

**Expected:** product created + redirect, or a visible error. **Actual:** silent 500; admin believes the save succeeded. Blocks the primary manual product-creation workflow.

## Gaps (not safely / not fully tested on prod)

- **Mobile (390px) for orders & purchases:** BLOCKED — the qa-orders agent's auth expired ~15 min in (reloading `admin-auth.json` did not restore the session); the first mobile navigation landed on `/login`. Orders/purchases mobile layouts were never verified. (Other agents' auth held; Products/Analytics/Customers/Home mobile were covered.)
- **`/purchases/$id` detail:** no purchases exist in the store, so the detail route could not be exercised at all.
- **`/orders/$id` detail happy path:** unreachable — see P1-1 (route throws for every order), so no valid detail render was ever observed.
- **All create submits end-to-end:** add-product blocked by the 500 (P0-1); add-category/brand blocked by the empty-URL validation (P1-2); add-order/purchase are silent no-ops (P2-5). No QA TEST record was successfully created, so no cleanup was needed and no real data was mutated.
- **Image/logo/banner upload** in add dialogs: not exercised (would create real CDN objects; also means the P1-2 validation couldn't be bypassed to confirm a working create path).
- **Destructive & mutating actions** deliberately not executed per prod-safety: delete/edit-save on real products/brands/categories/customers/orders; order status mutations ("Илгээх" send, "Хүргэсэн" delivered — no confirmation dialog seen in DOM, recommend verifying a guard exists); zero-stock action; payment / bank-transfer confirmation (Customer_claimed_paid → Success); AI re-fetch / AI Amazon import (external fetch); logout.
